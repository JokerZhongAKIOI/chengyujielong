# GOJ 题面 PDF 转 Markdown（`goj-pdf-to-markdown.user.js`）

goj.wiki（Hydro）题目页上的用户脚本：把题面里嵌着的 PDF 认出来，转成 Markdown（公式是 LaTeX）并复制到剪贴板。
题单（训练）页可以一次性复制里面所有题目的题面。还可以把题面发给原题机（yuantiji.ac）
一键搜原题：列出最像的 3 道，带相似度、原题链接和 VJudge 链接，还能取本题的简要题面单独显示（见下面第 9 节）。

- 脚本本体：[`goj-pdf-to-markdown.user.js`](goj-pdf-to-markdown.user.js)（直接装进 Tampermonkey / Violentmonkey）
- 纯函数测试环境：`npm install` 后 `npm test`（Node + pdf.js，跑的是脚本里的同一份代码）
- 转换结果长什么样：[`docs/示例-2085-葫芦娃救爷爷.md`](docs/示例-2085-葫芦娃救爷爷.md)（28 处公式全部是 LaTeX，可以直接粘）

## v2.15.0 修了什么

### 1. PDF 里的公式被“打印”成矢量图形时，整句缺公式

有些题面 PDF 是从网页 / Word 打印出来的，公式不是文字，而是**矢量轮廓**（曲线填色）。
文字层里这些公式只剩下一个空格，于是转出来是：

```
有 个葫芦娃，第 个葫芦娃的战斗力是 ，在第 天早上出生。
```

（原来会多一个空格，看起来“扫不出 KaTeX”；其实 PDF 里确实没有这些字符，不是解析器坏了。）

现在脚本会把 PDF 的绘制指令还原成“图形 bbox”，和文字行的空隙对起来（见脚本里的 3c 一节）：

- 落在文字行空隙里、大小又和字号相当的封闭图形 → 认定这里有一个公式，插入占位符；
- 独占一行、上下都是文字行的图形簇 → 同样认定是公式；
- 背景块、表格线、插图、页面边框都会因为“太大 / 太细”被排除；
- 独占一行的大公式（分数、求和那种，上下都是文字行）同样认得出；
- 公式真文字（文字层里有 `≤`、`n`、`10^5`）的 PDF 一处都不会误报（`tools/fixtures/plain-text-math.pdf` 就是这条的回归用例）。

补全方式（按设置里的“PDF 识别方式”）：

| 情况 | 结果 |
| --- | --- |
| 自动 / AI + 配了视觉模型 API | 把一页里的公式裁成一张带编号的竖条拼图，**一次请求**转成 LaTeX，逐处填回原位 |
| 只读文字层 / 没配 API | 公式换成该处的截图（`![公式](data:image/png;base64,…)`），信息不丢；可在设置里关成 `[公式]` 占位 |
| 模型没认出来的某一处 | 同样退回截图 / `[公式]`，并在末尾提示块里说明补了多少、剩多少 |

一次请求只补一小块图，比把整页渲染给模型便宜得多；“只补公式”的页数也算进自动模式的页数上限，
超过上限（12 页）不会自动烧 API，而是等用户手动点。

### 2. 上传的文件本身被“另存为 GBK”毁过

仓库里这份脚本能正常跑：`插件.js` 被某个工具用 GBK 保存过，凡是 GBK 编不出来的字符（emoji、`≤ ≪ ≅ ∓ ∂ ⟨ ⌊ ℕ √ …` 这些数学符号）
全被写成了 `?`，其中

```js
const body = markdown.replace(/?PDF:(\d+)?/g, …)     // 坏正则，脚本直接 SyntaxError
const SYMBOLS = { '≤': '\\le', '?': '\\le', … }      // 数学符号表被削掉一半
MATH_TRIGGER_RE / BULLET_CHARS / 界面文案里的 emoji    // 同上
```

已经全部按上下文还原，并把 `?PDF:n?` 这种占位符统一成不会被编码吃掉的 `%%PDF:n%%`
（同一个坑：`%%H页-序号%%` 是公式占位符）。还原脚本留在 `tools/reconstruct_gbk_damage.py`，替换清单和原因都在里面。

界面文案里的 emoji 属于“看着不对但不影响功能”的一类，是按上下文猜回来最合理的那个（⚙️ 设置、👀 面板、📋 复制…），
如果你有原始文件，可以直接用原文件覆盖这一段。

### 3. 复制出来的 Markdown 不再有杂音

- 题面里嵌了 PDF 的题目，正文里原来会残留一个孤零零的 `%%`（占位符 `%%PDF:0%%` 只替换了前半截）；
- 末尾的「⚠️ 第 1–2 页有 28 处公式是矢量图形…」提示块原来是引用块，会跟正文一起被粘进输入框，
  现在写成 HTML 注释：渲染出来看不见，翻源码才看得到（面板的日志里仍然照旧）。

### 4. 没配视觉模型 API 时的截图更清楚

公式退化成截图是**兜底**，不是终点：这些位置的字符在 PDF 里根本不存在，只有看图才能变成 LaTeX。
这一版的截图：

- 分辨率提高（整页按 2400px 宽渲染，约 4 倍），并把四周的空白裁掉，剩下的白边只有 3 像素；
- 上下按整行的字带宽裁，上下标、根号、求和号的上下限不会被切；左右只留一点点，
  不会再带进旁边的汉字；
- 28 处公式的截图总共约 60 KB（原来 90 KB），粘进编辑器也不会太沉。

没配 API 时，右下角按钮会直接显示「🔑 已复制 · 28 处公式是截图，点这里转成 LaTeX」，
点一下就能去填接口信息，回来再点一次即可。

### 5. 题面页面里已经有 LaTeX 时，不再把同一份 PDF 又复制一遍

有些题目的题面是 Markdown 写的（Hydro 用 KaTeX 渲染，公式是现成的 LaTeX），旁边另外挂了一份
打印版 PDF。以前脚本会把两份都复制下来：题面是漂亮的 LaTeX，紧接着又多出一整份 PDF 的正文
（公式是截图 / `![公式](data:image/png;base64,…)`），粘到题目输入框里全是噪声。

现在会先比一比：**题面页面里已经有 LaTeX 公式**、而这份 PDF 的内容和它基本重合（按 6 字一组的
字串算重合度，≥ 80% 就算同一份）时，就跳过这份 PDF —— 不裁图、不调 API、正文里也不留痕迹，
只在面板里记一句「跳过：题面页面上已经有这一段（重合度 97%）」。题面还是英文、PDF 是中文这种
“两份不一样”的情况不会误判，照旧两份都留，面板里也会写明「和题面重合度 41%，不像同一份，照旧识别」。

算重合度时只比正文的字：公式、图片、链接、样例代码块、脚本自己的 `%%PDF:n%%` / `%%H页-序号%%`
占位符，以及所有数字都不参与（样例数据在 PDF 里是一行行散开的数字，在题面里却躺在代码块里，
拿它们比只会把“同一份题面”误判成不重复 —— v2.5.0 就是这么把 2085 的重合度算成 76%、把题面里
嵌的那份 PDF 又复制了一遍的）。题面正文太短（两边加起来不到 40 个字）时不判重，照旧两份都留。

顺带把公式源码的来源补齐了（都能还原成 `$…$`）：

| 页面里的样子 | 还原方式 |
| --- | --- |
| KaTeX（Hydro 默认） | `<annotation encoding="application/x-tex">` 里的源码 |
| MathJax v2 | `<script type="math/tex">` 里的源码（`mode=display` 的自动独立成行） |
| `data-tex` / `data-latex` / `data-formula` / `data-math` | 属性里的源码 |
| `<img>` 的 `title` / `alt` 里就是源码（有些转换工具这样存） | 直接当公式，图不粘进来 |

跑的时候面板会记一行诊断，装好后看一眼就知道题面是从哪儿来的：

```
题面：1234 字，含 LaTeX 公式；PDF 1 份（页面上的公式：KaTeX 12 处 ｜ MathJax 0 处；题面区域：div[data-fragment-id="problem-description"].section__body.typo）
```

- 写「没有公式源码（… KaTeX 0 处）」：页面上确实没有公式文字（公式是画出来的 / 在 PDF 里），
  那就只能靠 PDF 那条路（配视觉模型 API）。
- 写「没有公式源码」但页面上有公式（KaTeX / MathJax 不是 0 处）：多半是题面区域认错了，
  面板会再补一句 `⚠️ 页面上有 N 处公式，但没有一处落在题面区域（…）里`，把这两行发给作者就能定位。
- 写「含 LaTeX 公式」：公式直接来自页面，题面里嵌的重复 PDF 会被跳过。

### 6. 新增 DeepSeek / OpenRouter 预设

设置面板的「快速填充」里多了 **DeepSeek**：接口地址 `https://api.deepseek.com/chat/completions`、
模型名 `deepseek-flash`、自动关思考（`{"thinking":{"type":"disabled"}}`），选中时面板底部会把该预设的注意事项写出来。

要点（都是官方文档里的硬性限制，填错了会直接报错）：

* 官方**只有 `deepseek-flash` 一个模型能收图片**；`deepseek-v4-pro` / `deepseek-chat` 传图返回 HTTP 400；
* 一张图无论多大，最多按 **1024 token** 计费，接口地址填 `https://api.deepseek.com` 也能用（脚本会补上 `/chat/completions`）；
* 现在是**按 token 计费**（高峰 / 非高峰两档价），新账号可能带一笔赠送额度，以控制台余额为准 —— 当作“免费额度”用没问题，但别当成长期免费；
* 想继续白嫖就用上面的「智谱 GLM-4.6V-Flash（免费）」预设。

模型不吃图片时（把 DeepSeek 填成了文本模型、或换成别家的纯文本模型），报错会直接写成
「这个模型不接受图片输入（HTTP 400）：… 得换成支持图片的模型：DeepSeek 用 deepseek-flash，智谱用 glm-4.6v-flash」。

**OpenRouter** 也加上了：接口地址 `https://openrouter.ai/api/v1/chat/completions`，默认模型
`nvidia/nemotron-3.5-super-vl:free`（免费、专门做视觉理解）。要点：

* OpenRouter 的免费模型**ID 都以 `:free` 结尾**，余额 0 也能用，但**按次数限流**：约 20 次/分钟、**50 次/天**
  （一次性充 10 美元后升到 1000 次/天）。一道题通常 1~2 次请求，日常够用；
* 免费模型会轮换。要换模型时去 [openrouter.ai/models?max_price=0](https://openrouter.ai/models?max_price=0)
  挑一个带 **Vision** 的，把 ID 粘进「模型名」（例如 `google/gemma-4-31b-it:free`）；
* 有些模型默认开思考 —— 在「额外请求参数」里填 `{"reasoning":{"enabled":false}}` 关掉，转写题面不需要想；
* 免费次数用完了会报「免费模型今天的次数用完了（HTTP 429）：…（默认约 50 次/天，一次性充 10 美元后升到 1000 次/天）」。

> 选哪个？**纯白嫖优先智谱 GLM-4.6V-Flash（免费、不限次数、但并发 1）**；想多几个备选就用 OpenRouter 的 `:free`；
> 不在意几毛钱、想要最稳的用 DeepSeek `deepseek-flash`。

### 7. 备用接口：主 / 备用一键来回切，一套挂了自动换另一套

设置里多了一组「备用接口」（接口地址、API Key、模型名、额外请求参数，每一项都有和主接口一样的「快速填充」下拉框）。两套都填好后：

* 面板上出现 **⇄ 切到备用（模型名）**：点一下就把配置翻到另一套、并立刻用新接口重跑一遍，按钮随即变成「⇄ 切回主接口」——**来回切不用重新填 Key**；
* **一套挂了自动换另一套**：额度用完（HTTP 429）、Key 失效（401 / 403）、模型不吃图片（400）……都会自动改用另一套再试一次，日志里写清原因、换到了哪套；同一次运行里之后就直接用能用的那套（不再白撞主接口）；
* 设置里「测试连接」测的是当前选中的那套，「测试备用接口」只测备用接口 —— 都只发一次请求、**不会**自动换另一套（免得给你一个假的“连接成功”）；
* 备用接口只填了一半（比如只粘了 Key）会明确提醒：地址 / API Key / 模型名要一起填，或者全留空；
* 老配置不用管：没配过备用接口时读出来就是空的，行为和以前完全一样。

典型搭配：主接口放免费的 **智谱 GLM-4.6V-Flash**，备用放 **DeepSeek `deepseek-flash`**（或反过来）——
免费额度用完 / 被限流时自动兜底；OpenRouter 的 `:free` 模型每天只有约 50 次，也可以拿它当备用。

### 8. 题面原文直接读站点数据；题面本身就是 PDF 时，面板会说明白

Hydro 会把这一页的数据写在页面里（`window.UiContextNew` → `pdoc.content`，就是题面的**原文**）。
脚本现在会先读它：

| 站点原文的样子 | 脚本怎么办 |
| --- | --- |
| Markdown 带 `$…$`（或 `@[pdf](…)` 之外的正文） | **直接用它当题面** —— 比从渲染结果里扒可靠（页面上的 KaTeX 也一样准，但原文不受渲染影响） |
| 只有 `@[pdf](./2085/file/statement.pdf?tid=…)` 这一句 | 说明**这道题的题面本身就是一份 PDF**：把这份 PDF 当题面，面板里直说「题面本身就是一份 PDF」 |
| 没有站点数据（别的站点 / 改了模板） | 照旧从页面 HTML 里提取 |

反过来的情况也修了：**站点数据里有题面原文，但页面结构不是 Hydro 默认模板**（题面区域认不出来，
以前会直接报「没有找到题面区域」）时，改用站点数据里的原文，照常导出。面板第一行会写成
`…；题面区域：没找到（这个模板和 Hydro 默认的不一样），题面读的是站点自己带的数据`。

顺便还修了两件小事：比赛结束时 Hydro 会在题面顶部插一句「该比赛已结束…」，那不是题面，不会再被复制；
题面里的 PDF 链接（站点原文里的 `@[pdf](…)`）也能当 PDF 来源兜底，DOM 里没嵌 `<object>` 时也认得出来。

> 有些题的题面**只有一份 PDF**（比如「葫芦娃救爷爷」：站点原文就是 `@[pdf](…/statement.pdf)`，
> 页面上 KaTeX / MathJax 都是 0 处，PDF 里那 28 个公式是**画出来的矢量图形**，文字层里没有字符）。
> 这种情况想拿到**真 LaTeX**（而不是截图）只能靠视觉模型，见下面「配一个免费的视觉模型」。

### 9. 搜原题：一键去原题机找最像的原题（前 3 道，带相似度和链接）

面板上多了一个 **🔎 搜原题**（油猴菜单里也有）：把转好的题面发给原题机
[yuantiji.ac](https://yuantiji.ac) 的公开接口 `POST /api/search`，在面板里列出**最像的 3 道**。
先说清：这是第三方维护的免费公益站（语料约 25 万道、60+ 个 OJ），**没有官方接口、没人承诺它一直可用**；
它挂了的时候面板会把错误写明白（并提示可以打开网站手动粘题面），不会影响转写和复制。

**自动选 Expert 模式。** 网站上的 Simplified / Expert 是界面差别，落到接口参数就是一组开关，
脚本固定发 Expert 的完整组合，一次请求拿最终结果：

| 参数 | 含义 | 脚本发的值 |
| --- | --- | --- |
| `query` | 拿去检索的题面（最长 16000 字） | 转好的题面清洗后截到 15000 字：去掉页眉、插件提示、图片（base64 公式截图又长又占额度），LaTeX 原样保留 |
| `k` | 返回几道 | `3` |
| `rewrite` | 先用模型把题面重写成简洁描述再检索 | `true` |
| `skip_short` | 跳过过短题面（垃圾结果过滤） | `true` |
| `rerank` | 用重排模型把候选（站内固定先取 100 道）重排一遍 | `true` |

每道结果显示：

* **相似度**：题面语义相似度 `cos`（百分比；旁边小字是 `cos 原始分 · 重排分 rr`）。
  经验阈值：≥ 90% 标「几乎肯定是原题」，≥ 85% 标「很可能是原题」——但这只是语义像不像，**点开核对后再下结论**；
* **原题链接**：接口直接给的原站地址（点题名也是它）；
* **VJudge 链接**：接口没给，按结果的 `uid`（形如 `CodeForces/1784C` = Source/题号）拼
  `vjudge.net/problem/{OJ}-{题号}`（CF 的 6 位比赛号自动改挂 Gym）。只对题号能直接对上的 OJ 拼
  （CodeForces、AtCoder、CodeChef、SPOJ、POJ、LibreOJ……一张约 50 项的表），不在 VJudge 上的 OJ 不硬给链接；
* 同一道题在别的 OJ 也出现时（接口的 `also` 镜像）会一起列出来；每道下面还有它自己的**简要题面**
  （默认只露 3 行，点「展开它的简要题面」看全文），不用打开链接就能先对一眼是不是同一道题。

**本题的简要题面单独显示。** 同一次搜索还会带回原题机给**这道题**重写的简要题面
（接口的 `rewrites`，没有单独的接口，跟着搜索一起返回）：`t0` 是去掉故事背景、译成英文
但信息齐全的题面（网站上叫「重写 1」），`t1` 是一段更抽象的题意（「重写 2」，会直接把题
说成背包之类）。面板上有单独的 **📝 简要题面**按钮（油猴菜单里也有）：已经搜过就直接
滚到那一块，没搜过就（顺带）搜一次取回来；简要题面显示在结果区最上方的一块独立区域里，
有自己的「复制简要题面」，复制出来是一份 `## 简要题面` 的 Markdown（用「复制结果」拿
整份搜索结果时它也排在最前面单独成节）。简要题面区里有「翻译成中文」：点一下就用 Google 翻译的免费接口
（优先用 translate.google.com 网页版同款的 batchexecute 接口，被限流时自动依次换 client=at、gtx（POST）两个免费接口重试，都免 Key；公式 `$…$` 会先占位保护再翻、译完换回）
把本题的简要题面译成中文，可与英文原文来回切换，「复制简要题面」复制的是当前显示的
那种语言；每道搜到的原题下面的简要题面也能单独翻译。简要题面区还有「预览」：照 Markdown 文章阅读器的方法——markdown-it 把 Markdown 渲染成 HTML 并关掉原始 HTML（第三方文字不能注入）、公式用加在 markdown-it 上的数学规则交给 KaTeX 排版——把简要题面渲染出来读（中英文都可，跟着当前显示的语言走）；只预览简要题面，题面正文不动。都是点了才发（不自动发给 Google），
连不上（国内网络多半要代理）会在日志里说明。说到底它是模型改写的题面、又经一层机翻，
只是帮你快速看懂题在问什么，细节仍以原题面为准。

结果只在面板里显示、写日志，**不混进题面 Markdown**；想把结果存下来，点结果区的「复制结果」，
得到的就是一份 `## 原题搜索` 的 Markdown（相似度 + 两个链接都在里面）。

其他细节：没有 API Key 这回事（公开接口，靠油猴的跨域请求绕开浏览器的 CORS）；一次搜索对方要
跑重写 + 嵌入 + 重排，通常十几秒，脚本里两次搜索至少隔 3 秒、失败只重试一次，别连点；
还没转写过而题面正文在 PDF 里时，会自动先只读文字层把题面取出来再搜（不调视觉模型、不动剪贴板），
扫描件取不出文字会直说「先转一遍再搜」。设置里有「转写完成后自动搜原题」开关，**默认关闭**——
毕竟每次都会把题面文字发给第三方，要不要自动发由你决定。

### 10. 一整场模拟赛的 PDF：抠出与本题同名的那一道（纯本地，不用 API）

有些题的题面直接放了**整场模拟赛的 PDF**（封面 + 好几道题装在一份文件里）。以前版本已经会按
题名只取同名的那一道，但只认“标题样式”的题名：Word 排版的模拟赛卷子里，题名常常与正文同字体、
字号只大一点点，转写出来只是一行普通段落（还经常和元信息并成一行，如
`2. 星际旅行源程序文件名：travel.cpp 输入文件名：travel.in …`），于是分不出题、只能整份复制
并提示你自己删。这一版把分题算法扩展到这种版式，全部在本地完成：

* **题名候选放宽**：除了标题行，还认正文里带题号的行（`1. / 2. / 3.`、`（二）`、`T2`、题一……；
  非特指的序号要用“序号成串出现 + 每段后面都有题目描述/输入/输出小节”来证明自己，封面清单和
  正文编号列表过不了这一关），以及独占一段、后面紧跟小节标题的无序号短行（粗体题名最常见）。
  题名与元信息并在一行时，先把“源程序文件名：…”那截切下来单独保留，切题时仍会出现在题面里。
* **分界靠小节重复校验**：一道题里“题目描述 / 输入 / 输出”各只出现一次，再次出现就是新的一道——
  单个候选误报顶多被并进当前题目，切不出假题来（专门有防误拆的测试）。
* **对上号的办法变多了**：除了题名相似度，还会看每道题开头几行——题名写在“第二题”的下一行、
  或本题在站上只叫英文文件名（`travel`，真名只出现在「源程序文件名：travel.cpp」里）时都能对上。

抠出来后与以前一样：面板日志会写「PDF 里有 3 道题，取了第 2 题《…》（相似度 …）」，也可以在
👀 面板的下拉框里改选别的题或整份；实在分不出来仍是整份复制 + 一句明确提示，不会悄悄截错。
回归夹具有真实版式的 `tools/fixtures/mock-contest.pdf`（封面 + 三道题，生成器在 `tools/make_fixtures.py`）。

> **2.11.1 追加**（在一份 ZJOI2021 模拟赛卷子上实测后补的）：小节名没能变成标题行时
> （独占一行的裸文本「题目描述」、或段首加粗的「**题目描述** 给定…」），以前分题引擎根本
> 数不到小节、自然切不开——现在这两种都算小节；LaTeX 编号标题「1 字典树」的计分不再被
> 数字打折压到及格线边缘；万一正文里连题名行都没有（题名只在封面表里），会直接按
> 「描述/输入/输出」的循环兜底切开，切出的题在下拉框里叫「第 k 题（没认出题名）」，
> 至少能手动选。实在分不开时，提示行末尾会带一条诊断（候选题名个数），发给作者好继续对症下药。

### 11. 生成 PDF 下载

面板上有「📄 下载 PDF」：把文本框里当前的题面 Markdown 用与预览相同的
markdown-it + KaTeX 排版，再在浏览器里用 html2pdf（html2canvas + jsPDF）
生成一份 A4 的 PDF 直接下载（文件名是 `题号 题名.pdf`，你手改过文本框
就按改后的生成）。简要题面区也有自己的「下载 PDF」，生成当前显示语言
的那一版简要题面。

排版在一张隔离的隐藏页里完成（自己的样式 + KaTeX 官方 CSS），免得被
站点页面样式干扰、也避开 html2canvas 不认的站点 CSS。生成的是
**图片型 PDF**（每页是排版好的图，看和打印都清楚，但文字不能选中复制——
要文本请用 Markdown 本身）。内容特别长（比如整题单合并）时可能因为
浏览器画布上限失败，日志会说明；外站图片若不允许跨域读取，在 PDF 里
会缺失（题面自己的图床一般是同源，没事）。

#### 配一个视觉模型（可选，但题面只有 PDF 时就需要）

| 预设 | 模型 | 花钱吗 | 备注 |
| --- | --- | --- | --- |
| **智谱 GLM-4.6V-Flash（免费）** | `glm-4.6v-flash` | 免费 | **最省事**；同一个 Key 同时只能发 1 个请求，“并发数”填 1 |
| **DeepSeek** | `deepseek-flash` | 按 token 计费，很便宜 | 官方接口；一张图最多 1024 token，转写时用的是关掉思考的 V4.1-Flash |
| **OpenRouter（免费视觉模型）** | `nvidia/nemotron-3.5-super-vl:free` | 免费（按次数限流） | 聚合平台；`:free` 模型约 50 次/天，模型会轮换，可自己换 |
| 硅基流动 SiliconFlow | 按平台文档 | 平台上有永久免费的视觉模型 | 模型名要自己填 |
| OpenAI / Gemini | 按官方文档 | Gemini 有免费额度 | 模型名要自己填 |

怎么配（以免费那条为例）：

1. 到 [bigmodel.cn](https://open.bigmodel.cn/)（智谱开放平台）注册，控制台里新建一个 API Key；
2. 题目页右下角点 `🔑 …`（或齿轮 → 设置），预设选「**智谱 GLM-4.6V-Flash（免费）**」，把 Key 粘进 `API Key`，保存；
3. 回到题目页再点一次按钮。逐处公式会裁成小图交给模型，只补公式、不动正文。

选用「**DeepSeek**」时：接口地址和模型名会自动填成 `https://api.deepseek.com/chat/completions` + `deepseek-flash`
（`deepseek-v4-pro` / `deepseek-chat` **不能看图**，传图会返回 HTTP 400；脚本会直接把这句话翻译成“这个模型不接受图片输入，
请换成 deepseek-flash”）。官方是按 token 扣费的，新账号可能带一笔赠送额度，具体以
[platform.deepseek.com](https://platform.deepseek.com/) 控制台里的余额为准 —— 别把它当成长期免费额度。
另外脚本已经替你关掉了思考模式（`{"thinking":{"type":"disabled"}}`），转写题面不需要想，关了更快更省。

实测「葫芦娃救爷爷」：2 次请求（每页 1 次）、28/28 处公式变成 LaTeX，
按钮显示 `✅ 已复制 · 1167 字 · 文字层 + 视觉模型`。结果见
[`docs/示例-2085-葫芦娃救爷爷.md`](docs/示例-2085-葫芦娃救爷爷.md)。

## 安装

1. 装 Tampermonkey / Violentmonkey；
2. 新建脚本，把 `goj-pdf-to-markdown.user.js` 的内容粘进去（或直接把文件拖进浏览器）；
3. 打开 goj.wiki 的题目页，右下角出现「📋 题面转 Markdown」即安装成功。

首次使用建议在设置里：

- 「PDF 识别方式」保持**自动**（不配 API 也能用，公式会退化成截图）；
- 「识别不出的公式改用截图」默认勾选。

想要公式变成 LaTeX（而不是截图），需要接一个能看图的模型。**智谱 GLM-4.6V-Flash 是免费的**，三步：

1. 打开 [bigmodel.cn](https://bigmodel.cn) 注册登录 → 控制台 → 「API Keys」→ 复制一个 Key；
2. 在题目页右下角点 ⚙️ 设置 → 「模型」下拉里选 **智谱 GLM-4.6V-Flash（免费）**
   （接口地址和模型名会自动填好）→ 把 Key 粘进「API Key」→ 保存；
3. 回到题目页点「📋 题面转 Markdown」，公式会被裁成带编号的竖条拼图一次请求转成 LaTeX。

免费档限 1 并发，插件一次只发一个请求，不受影响。硅基流动（SiliconFlow）、OpenAI、Gemini 也都有预设，填接口地址 + 模型名 + Key 即可。

## 开发

```
npm install          # pdfjs-dist（跟脚本里 @require 的版本一致）+ @napi-rs/canvas（Node 里渲染页面用）
npm test             # 55 个测试，覆盖矢量公式检测、版面、模型回复解析、端到端流程
npm run fixtures     # 重新生成 tools/fixtures 下的测试 PDF（需要 python3 + reportlab）

# 拿一份 PDF 直接跑整条链路（不需要浏览器）：
node tools/harness.cjs tools/fixtures/p2196-fhllyjyy.pdf --engine text
node tools/harness.cjs tools/fixtures/p2196-fhllyjyy.pdf --engine auto \
  --fake-ai "$(cat tools/fixtures/p2196-answers.json)"    # 用核对好的标准答案跑一遍完整流程
node tools/harness.cjs tools/fixtures/p2196-fhllyjyy.pdf --engine auto --statement /tmp/题面.md
                                                          # 模拟“题面页面里已经有 LaTeX”：这份 PDF 会被判为重复、跳过
node tools/harness.cjs tools/fixtures/p2196-fhllyjyy.pdf --dump-pages      # 看每页检测到的公式洞
DUMP_STRIP=/tmp/strip{n}.png node tools/harness.cjs …                      # 把交给模型的拼图存下来看
```

`tools/harness.cjs` 会把脚本里除了 UI 之外的全部逻辑跑一遍（`recognizePdf` → 文字层 → 矢量公式 → 版面分析 → Markdown），
`--fake-ai` 用一个假的 chat 回复模拟视觉模型（`{"strip": {"1": [...], "2": [...]}}` 可以按页给答案），
所以整条链路可以离线测试。`tools/fixtures/p2196-answers.json` 是 `p2196-fhllyjyy.pdf` 里
28 处公式的**人工核对结果**，`npm test` 用它验证“公式有没有补到句子的正确位置”。
